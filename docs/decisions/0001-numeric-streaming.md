# ADR 0001: Borrowed ZIP entries and owned sparse output

Status: implemented for the first M1 checkpoint.

`WorkbookReader<R: Read + Seek>` owns the ZIP archive and small sheet catalog. `Rows<'a, R>` borrows one ZIP entry exclusively and streams decompression through a 32 KiB input buffer and namespace-aware XML events. This avoids self-referential owners, unsafe lifetime extensions, and whole-sheet buffering. A reader must be dropped before selecting another sheet or recovering the source with `into_inner`.

Adapters can consume owned `Row`/`RowBatch` values or keep the workbook in an adapter-owned handle and create readers within its operations. No foreign runtime or stable ABI belongs in core. A future independent reader can reopen a source if simultaneous sheets are required; this checkpoint does not promise concurrent readers from one source.

Numeric/empty values, typed addresses, errors, limits, and sparse output belong to core. XLSX owns XML/ZIP/package semantics. The public facade exposes these shared types, never calamine types. The selected upstream code was refactored rather than retaining its eager strings/styles or Range collection. Coordinate validation is shared. Namespaces and end tags remain checked. Relationship IDs determine paths; dimensions never determine allocations.

Projection checks the current coordinate before decoding values, covering openpyxl MR !454's stale-counter risk. Excluded cells are still scanned for XML structure and coordinates; their value semantics are not validated. Full consumption reads the worksheet tail through EOF, including CRC validation. Early drop releases the borrowed entry without draining it or verifying unread CRC. Workbook drop releases its source; no process-exit registry is used (!472).

`read_row_into` clears/reuses a caller-owned vector. `next_row` returns an owned sparse row. Batches account for outer and inner vector capacity, and may retain one additional bounded lookahead row. A row exceeding a batch's byte budget fails rather than exceeding that budget. Retaining multiple outputs is caller-owned additional memory. Caller-supplied buffers may already have allocations larger than configured limits; limits do not retroactively control external allocations.

`read_sheet` is an explicit non-streaming public operation: it collects all sparse rows through the same decoder into owned `SheetData`. It accounts for retained outer/inner capacities against `max_materialized_bytes` (256 MiB by default), with one current bounded row and parser/catalog state as additional working memory. Errors discard partial output and release the entry. This is a numeric snapshot for repeated access, not the later editable workbook. No first-read speedup follows from collection alone. Input buffer size is independently configurable. The user requires future intelligent Auto allocation and mode selection; see [ADR 0002](0002-adaptive-memory.md).

Limits cover compressed archive size before ZIP parsing, entry count and declared aggregate size after ZIP catalog creation, combined metadata bytes, actual per-part XML bytes, per-event consumed bytes, XML depth, decoded value bytes, and row/batch allocations. Event input is capped before quick-xml can accumulate unlimited content. Its vector and namespace buffers, allocator overhead, ZIP internals, and metadata containers mean these are component budgets, not an exact whole-process RSS cap. ZIP central-directory allocation precedes entry-count enforcement; a future hardened package scanner may add a pre-allocation directory budget. Metadata/catalog costs can grow with bounded file complexity, not worksheet row count.

This numeric checkpoint represents raw numbers as `f64` and does not read style tables. Large integer literals may round; M2 must preserve the baseline's exact integer semantics. Nonzero styles are rejected; style zero is raw numeric, including when its format is customized. It cannot infer dates, inherited row/column formatting, or formula cache semantics. M2 must introduce shared value/style/date/formula models rather than silently treating those capabilities as complete. Strings require the planned bounded/disk-backed shared-string strategy. Writers/editing/preservation remain explicit future modes.

Correctness uses generated in-memory OOXML fixtures, plus openpyxl-generated interoperability benchmark inputs. Benchmarks measure release binaries, openpyxl read-only, and calamine's materialized Range across three row scales. They include process startup and discovery, exclude generation/build, record checksums and kernel peak RSS, and use no temporary files during reading. The native measurement launcher is benchmark infrastructure only; the library remains safe Rust with unsafe forbidden.
