# ADR 0004: Bounded scalar spooling and explicit workbook publication

Status: M3 sequential creation acceptance complete.

The selected rust_xlsxwriter constant-memory packager streams an on-disk cell section between worksheet metadata sections. crabxl adapts this flow to one owned worksheet temporary file per sheet, one active file buffer, and one bounded reusable encoded row. Completed worksheets retain files, names, and catalog metadata, not resident XML. Finalization rewinds and copies files into ZIP. The existing core CellValue/Row/address/error types are used directly; no upstream workbook/value/style types are exposed.

WorkbookWriter starts sheets sequentially and accepts strictly increasing row indices. Its row encoder validates all coordinates and scalar values and bounds the encoded row before writing any of it. Validation/budget failures therefore leave the current sheet usable. A physical spooling I/O failure poisons the writer; subsequent writes and finish fail. Unlike upstream insert_cell, revisiting a flushed row returns InvalidState instead of warning and ignoring lost data. Creating a next-sheet temporary resource precedes closing the current sheet, so creation failure does not discard usable state.

WriteOptions controls temporary directory, active file buffer, shared catalog/style metadata and style count, encoded row/cell limits, total temporary bytes, per-sheet bytes, sheet count, and epoch flag. Temporary-byte limits include buffered XML and reserve the closing worksheet tag before accepting a row. WriteStats reports rows/cells and peak logical temporary XML; closing a sheet flushes it, allowing comparison with physical file sizes. These budgets do not include caller-owned rows/output, allocator overhead, or all ZIP dependency allocations; they are not a hard process RSS ceiling. New ZIP entries select ZIP64 from known temporary-file sizes; large-size interoperability remains to be tested.

Finish consumes the writer and packages into a caller-selected Write + Seek sink. Passing &mut W keeps caller ownership. Only successful finish produces a workbook; output errors may leave partial bytes and ZIP's Drop may attempt finalization. No atomic filesystem publication is promised by this low-level sink API. Abort removes all owned files, attempts every cleanup despite individual failures, and retains failed paths for subsequent cleanup attempts. Row/catalog/style buffers are released. Drop retries best-effort cleanup and never opens a publication sink or silently saves a workbook.

The checkpoint writes exact i64/arbitrary decimal integer literals, finite f64 literals preserving floating lexical identity, booleans, error tokens, plain inline text, physically empty cells, sparse rows, empty sheets, worksheet names/order, and the epoch flag. Shared normal formulas retain typed optional caches; absent/Empty caches omit v entirely. Dates carry a source epoch and date/time/duration interpretation; default date formats are automatic. Registered basic formats cover font, solid fill, four borders, alignment, custom number format and cell protection. Identical complete formats reuse IDs; component tables currently retain at most one component per format, bounded by the style/catalog budget. Font names and custom format codes enforce worksheet limits (31 and 255 characters). Reader normal formulas use the same model and include owned expression/cache payloads in row/batch/materialization budgets. CellValue remains 16 bytes; adding a shared StyleId increases Cell from 24 to 32 bytes and the release regression probe records its effect. All text retains whitespace and escapes XML; invalid XML characters and oversize values return errors without truncation. Literal OOXML escape-looking text is explicitly unsupported until an escape-aware codec can preserve both physical and interpreted semantics. This avoids copying the known string corruption risk into the writer.

Complete read-side style/date codecs, advanced/named/theme styles, non-normal formulas, rich/shared strings, images/features, non-seekable output and existing-file editing/preservation remain staged. The initial shared style model does not imply complete M5 style support. Style IDs are workbook-local; caller-created IDs must reference registered records. Calendar dates with an explicit style require an appropriate date/time number format. Windows serial 60 cannot change epochs; its calendar helper maps to February 28 as the pinned public baseline does. Tests cover scalar/formula round-trip, date/epoch boundaries, basic-style validation and deduplication, state/mode restrictions, row/metadata/temp limits, empty/multiple sheets, abort/Drop, cleanup failure/retry, next-file creation failure, and partial output I/O failure. Python public-API readback and release time/RSS/temp-space evidence are recorded in benchmarks/m3-writer.md. No upstream full test suite or Excel UI validation is claimed.
