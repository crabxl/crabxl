# ADR 0005: Sparse models and lazy original-package editing

Status: accepted for the first M4 checkpoint; M4 remains in progress.

Core `Worksheet` is an I/O-free sparse ordered map of owned shared cells. Borrowed access avoids payload clones; append and finite insert/delete/move/copy operations validate bounds and conservative work allowances before mutation. Destination holes clear overwritten cells. Styles and formulas move verbatim, without reference translation. `WorkbookWriter::write_worksheet` consumes borrowed cell iterators and preserves trailing empty row extent. A workbook aggregate and source structural edits remain required.

`WorkbookEditor` owns a seekable original ZIP and inventories parts without loading worksheet XML, images or macros. Pending values are sparse owned overlays. `set_value` validates payloads and budgets; physical cell existence and target metadata are validated during save. Existing styles and other attributes remain attached to the original cell. `upsert_value` inserts missing cells with default style, preserves inferred original coordinates, extends an existing dimension and rejects non-anchor merged cells. Typed date editing requires subsequent codecs.

Unchanged entries use ZIP compressed passthrough, preserving their payload bytes and relationship identities. Edited worksheets use bounded namespace-aware events, preserving unrelated subtrees, prefixes and attributes. Rewritten XML is semantically preserved rather than lexically identical. Shared-string entries and IDs remain unchanged; the optional reference count is omitted after edits. Every worksheet is scanned after an edit to remove old formula caches, and workbook calculation properties request automatic full recalculation. Caller-supplied new formula caches are retained. No calculation engine is provided.

Unknown parts, styles, comments, images and VBA are opaque preservation capabilities, not typed read/create/edit support. Signed packages, calculation-chain edits, AlternateContent in rewritten worksheets/workbooks, unsupported target children, cm/vm targets and non-normal target formula metadata are rejected rather than silently damaged. Full style/date catalogs, workbook sheet mutations and relationship-aware structural editing remain staged.

Editor overlays reuse reader Auto/Budget memory policy and expose the resolved allowance. Explicit patch caps further restrict retained overlays. Core charges 256 bytes per physical cell plus owned payload/name bytes; structural operations additionally reserve conservative working space. These are managed allowances, not exact BTreeMap allocation accounting or hard RSS ceilings. ZIP catalogs, caller data and allocator costs are additional. Editable models scale with loaded cells; lazy overlays scale with pending edits plus XML working buffers/catalogs.

Saving retains the original source and overlays for repeat saves. `clear_edits` reverts to that original baseline. `into_source` transfers ownership. Images are never copied into a second resident byte cache. `save_path` uses an adjacent temporary output ZIP and replaces its target only after success, including saves over the original path. Output storage therefore needs a full new ZIP alongside the old target; there are no worksheet XML temporary files. This is not an fsync/crash-durability guarantee. Caller-supplied output streams can contain partial bytes after failure, while the editor remains retryable.

By default, unchanged raw copies trust the input catalog CRC. `SaveOptions::verify_unchanged` checks unchanged payloads through bounded decompression before copying. Rewritten XML always consumes input to EOF and validates CRC. Tests cover limits, corrupted opaque CRC, output failures, atomic target protection and cleanup.

Original model/editor implementations reuse the shared codecs and foundational ZIP/XML/tempfile APIs. No additional upstream modules are imported. Existing encoder port provenance remains in third_party/ports.json. MR risks !458, !472, !473, !443/!445 and !439 motivate repeatable sources, cleanup, missing caches, namespace preservation and metadata guards.
