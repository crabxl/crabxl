# ADR 0019: Opaque themes and default package emission

## Decision

Core Theme owns immutable exact bytes with borrowed access and managed payload accounting. It is the representation for the public baseline's loaded_theme property, not a second drawing engine. WorkbookReader resolves the theme relationship, rejects duplicate/external relationships and lazily reads a bounded part with ZIP size/CRC verification. Normal row streaming never loads a theme. Repeated access borrows the same owned bytes. Themes and prepared styles consume the same remaining metadata input allowance regardless of access order; independent retained catalog limits still apply.

Public experiments demonstrate that loaded_theme accepts arbitrary nonempty bytes and saves them unchanged, even invalid XML or an unrelated root. Empty bytes select the default theme. Default theme access therefore preserves opaque data without attempting XML interpretation. validate_theme and ThemeWritePolicy::Validated are explicit stricter Rust extensions using bounded namespace-aware XML, event/depth/part limits and no document types. Custom retains the reference-compatible opaque behavior; Omit is explicit. Do not confuse opaque retention with parsed palette/font or theme editing support.

New packages emit the exact theme generated by the pinned public Workbook.save API. The static Rust literal uses ASCII Unicode escapes for script typeface names while preserving exact runtime UTF-8 bytes. This is generated package data, not reference implementation code. No per-writer default-theme heap copy is allocated. Custom theme payloads share the writer metadata allowance with the canonical registry and sheet catalog; abort releases them. Theme parts have their own content-type override and unique workbook relationship.

## Evidence and remaining scope

Tests cover default/custom/opaque/omitted themes, borrowed lazy access, configured byte limits, malformed strict documents, duplicate relationships, abort release, custom paths and shared theme/style input budgets in both access orders. Public readback checks exact bytes, including the default hash, empty fallback and opaque observations. Generation/provenance is in docs/research/default-theme-public.json and benchmarks/verify_themes.py.

Typed theme colors/font resolution, theme-aware rendering, loaded bank ownership and typed mutation remain staged. Existing editor opaque source preservation is independent of the new creation policy. Reader managed payload accounting excludes temporary parser/event buffers, allocator overhead and the ZIP dependency catalog. Auto aggregate work/retained budgeting is still pending; this checkpoint does not close M2/M4/M5.
