# ADR 0021: Joint managed read allowance

## Decision

read_with_policy uses one allowance after the configured parser/current-row working reserve. It charges managed package-name/catalog capacities, prepared styles/themes, shared-string tables, optional decoded caches, worksheet-local formula templates and library-retained sheet rows or active batch storage. Direct rows/read_sheet retain their independent component/data contracts. This is an operation-local managed allocation model, not a hard process RSS ceiling: ZIP dependency allocations, allocator overhead/reallocation transients, OS file cache and caller-held output are additional.

Styles are prepared under the remaining catalog allowance; existing catalogs that cannot fit fail without weakening their semantics. The shared-string component policy is clamped to the same pool while preserving caller storage and temporary-file limits. Auto can spill a previously prepared in-memory table when rows or templates need space, including after a tighter subsequent policy. Original entries remain usable if temporary output fails. Forced Memory never silently spills. Rebalancing preexisting caller-prepared storage can temporarily retain its prior allocation until the disk transfer succeeds; the new pool applies after that transition. Rich/plain entry identity and cache/source validation use the existing shared codecs.

No fixed fraction permanently partitions the pool among metadata families. Before a new shared template, bounded capacity/payload forecasting trims optional string caches or spills Auto table storage. Before library row/vector growth, retained capacity is charged and caches lend space; disk caches can rebuild when allowance becomes available again. Formula and string growth inspect each other's live accounted storage. Batch outer slots leave room for actual cells rather than consuming the whole small pool with row descriptors. Caller-held returned rows/batches are outside subsequent library retention; one bounded lookahead/current row is covered by the working reserve.

Repeated-access estimates account for non-evictable catalogs. Auto can rebalance a table to make predicted rows fit; actual later growth still runs under the shared allowance. Oversized partial models are discarded before reopening a stream; malformed values/format errors do not become successful fallbacks. ReadDecision exposes catalog/cache bytes and the initial row allowance; future templates and cache growth also consume it. Rows::managed_retained_bytes exposes the current policy ledger, excluding the reserved working space. Outside a policy stream this getter reports shared-string/template components only; WorkbookReader::catalog_memory_bytes reports managed package/style/theme catalog storage separately.

The pure memory_allowance helper remains runtime-independent of any workbook's loaded catalogs. read_with_policy applies its returned allowance to the actual live components. Availability remains a snapshot, with existing Linux/cgroup probing and explicit overrides; no speculative whole-sheet XML allocation or advertised-count reserve is added.

## Evidence and remaining scope

Deterministic tests cover catalog charges, bounded mixed strings/templates, prior-table rebalancing, strict Memory rejection, repeated-access lending, batch delivery and failed-spill source integrity/cleanup. Representative 2/256MiB mixed-policy measurements verify every text, shared expression/cache and styled date, with managed assertions outside timing and exact anonymous disk bytes reported. Previous rows-only budget behavior is measured explicitly rather than described as a process memory cap. Direct formula regressions remain recorded, including the observed large-case wall regression.

Projection/rich/data-only composition is now verified through read_with_policy_options (ADR 0022). Complete owned/loaded-bank catalog editing, dependency/allocator hard-limit control, broader platform probes and cross-package optimization acceptance remain staged. M2/M4/M7 completion is not implied by this checkpoint.
