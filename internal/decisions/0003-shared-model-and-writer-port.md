# ADR 0003: One shared model and a staged writer port

Status: M0 design accepted; writer implementation remains M3.

Core owns values, typed coordinates, workbook-local `StyleId`, errors, sparse rows, allocation accounting, limits, and memory policy models. The XLSX layer owns package relationships, namespace/XML codecs, number-format interpretation, and I/O. The facade exposes these types without upstream workbook types. M2 extends the existing value model and shared style identities; M3 serializers consume those models. Do not introduce independent calamine and rust_xlsxwriter value/style systems. A style ID validates identity syntax, not the existence or semantics of a workbook record; style zero must eventually be decoded from the style table.

The calamine source is pinned in ports.json. Its low-level cell reader already consumes events; eager styles/strings and Range collection are separate concerns. The port emits sparse rows/batches and explicit materialization. New scalar/string/date/formula codecs must reuse this path, including projection and resource limits, rather than add a second unchecked parser. Errors carry a common category and available part/cell/source context. Future adapters map language call syntax and conversions, while core remains runtime-independent.

The rust_xlsxwriter writer source is pinned at `902609b2e0fbc3cfa20fec5b464328479e29dbef`. Selected inspection covered `Workbook::add_worksheet_with_constant_memory`, `Worksheet::insert_cell`, `flush_to_row`, `flush_data_row`, and its constant/low-memory documentation. Constant-memory setup creates a temporary writer before changing workbook state, uses inline strings, and shares workbook format IDs. Advancing rows flushes prior data. Low-memory mode keeps shared strings, so it is not constant space for high-cardinality text.

An important porting risk: upstream `insert_cell` prints a warning and ignores edits to an already-flushed row. crabxl must return a typed mode/state error instead of silently accepting a lost write. The future writer must expose sequential mode restrictions, fallible finish, explicit abort/close, and best-effort owned-resource Drop cleanup. Drop does not silently save. Editable repeat saves remain a separate capability, including reusable image sources. Preserve borrowed caller resources. Record temporary-space, I/O, abandonment, and failure tests when M3 is implemented; the design alone is not verified writer support.

No additional spreadsheet source is selected in M0. Current package/scalar/string/style work has concrete calamine candidates, and writing has rust_xlsxwriter candidates. Pivot/complex round-trip gaps remain inventoried for M6; umya-spreadsheet evaluation is deferred until a specific module can be compared for licensing, preservation, and memory behavior. This is a source selection decision, not a removal of those features.
