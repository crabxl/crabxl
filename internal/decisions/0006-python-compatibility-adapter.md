# ADR 0006: Optional openpyxl-compatible Python adapter

Status: accepted at the user's request during M4. This changes the earlier binding deferral, not the independent Rust architecture or full baseline scope.

Use a separate optional the [standalone Python repository](https://github.com/crabxl/crabxl-python) Cargo workspace, PyO3 and Maturin. The facade/core/XLSX crates have no foreign-runtime dependencies. Python names and objects match openpyxl: Workbook, load_workbook, Worksheet/Cell access, one-based coordinates, append, iterators, editing and save. Extra diagnostics/resource controls may extend this API. Partial delivery must never require a different naming scheme or claim full compatibility.

Rust owns cell payloads, sparse models, package sources and pending overlays. Python Cell objects are weakly cached live views, so retained views follow structural moves; removed/overwritten views become detached values. Loaded worksheet materialization is lazy, explicit in the adapter implementation, and bounded by the same model allowance. Existing-cell assignment can use overlays without loading the sheet. Original reader/editor handles remain owned until close/drop and saves do not duplicate image bytes. Loading/saving/structural model work releases the GIL; Python conversion and short random access run under it.

Default model allowance derives from the shared Rust Auto policy. `max_memory_bytes` selects a managed model/operation cap; editor policy also reserves parser work. It is not a hard process RSS ceiling or aggregate cap across all sheets. Caller-held Python output/views, native dependency catalogs and allocator overhead are additional. A loaded materialized model and original overlay may both own pending values; materialization is a separate explicit cost from lazy edits.

New-model saves use the existing sequential writer with worksheet XML temporary storage, plus an adjacent full output ZIP before target replacement. Loaded saves use the preserving editor with an adjacent output ZIP and no worksheet XML spool. Path saves protect existing targets on reported failure; no fsync/crash-durability guarantee is implied. File-like adapters and read-only/write-only Python modes remain required future capabilities.

No runtime fallback to openpyxl is allowed. Test-only openpyxl 3.1.5 supplies the reference behavior. Unsupported properties are not silently accepted and lost on save. Exceptions include unsupported features, invalid coordinates/values, memory limits, I/O and closed handles. Complete upstream exception compatibility and all object attributes remain staged.

Selected release tests keep original method bodies, parameters and assertions. Only imports and fixture construction are adapted; a strict expected-failure marker records formula translation as unfinished M5 behavior. Provenance, revision, source hash and license are in https://github.com/crabxl/crabxl-python/blob/main/third_party/python-tests.json. The verifier reads test source only. Passing selected tests does not imply running or passing the entire upstream suite.

Initial coverage includes scalar/formula values, exact Python integers, millisecond datetime/time/duration creation, sparse append/iteration, cell identity and structural view updates, new-sheet naming/order, model renaming, borrowed writer output and preserving loaded cell edits. Full styles/dates/shared/rich-string reads, date-only object/format semantics, sub-millisecond datetimes, non-finite values, loaded structural edits, signature/calculation-chain handling, non-default workbook views, read-only/write-only and file-like binding modes remain explicitly planned. Core advanced feature models/codecs are not reconstructed in Python.
