# ADR 0045: Printing component ownership and reusable validation

PrintSettingsChange describes one owned component replacement. Canonical prospective accounting uses actual vector capacity and owned setup literal bytes without visiting unrelated vectors. PrintSettings::update validates and admits before moving components; failure preserves existing values, capacities and allocation identities. Worksheet and Workbook mutation facades apply the same operation under joint limits. Missing sheet metadata installs defaults only after successful admission; incoming payloads are dropped on failure rather than returned.

WorkbookEditor::update_print_settings reads and validates original printing metadata through EOF/CRC on its first mutation, then owns the resulting canonical model. Subsequent component updates use the admitted overlay without reopening the source or cloning unrelated breaks. Full snapshot replacements also reuse this original validation once a printing overlay exists. Printer relationship identities remain fixed to the validated original. XML and numeric invariants are checked before mutation, including setup literals. Clear discards validation ownership, so the next update reads the source again. Original-source getters remain separate from pending-overlay getters.

The first source parse and live overlays must fit their shared retained allowance. Later shrinking updates do not need a second full source model, so the previous shrinking-source regression case now verifies successful shrink under a crowded live-overlay budget. Oversized replacement components, invalid margins/XML and printer graph mutations remain atomic failures. Managed bytes account for actual capacity; retaining a source vector can cost more managed bytes than a fresh Vec::clone whose capacity equals length, despite avoiding repeated allocation. Benchmarks disclose both counters and RSS.

Tests verify allocation identity, moved replacement ownership, zero source bytes read after initial validation, repeated saves, clear/reload, unrelated workbook sheets and budget/XML/relationship failures. Public property and every-cell benchmark readback compare prior snapshot, current snapshot, current component and openpyxl behavior. This refactors the selected rust_xlsxwriter printing port into reusable canonical editing; it does not add another engine or complete M5 printing/binding coverage. Printer graph mutation, print names, header/footer editing and Python proxies remain staged.
